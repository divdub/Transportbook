## Spacing Scale

Declared from the existing `src/theme/spacing.js` tokens (provenance: codebase). The primary
8-point spine is **4, 8, 16, 24, 32, 48**. Two legacy tokens (`md=12`, `xl=20`) break strict
8-point but are pre-existing and wired throughout — **they are frozen as legacy, do not extend the
pattern with new non-multiple-of-4 values.**

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, label↔input gap, badge padding-y |
| sm | 8px | Compact element spacing, field-group gaps |
| md | 12px (legacy) | Default field gaps; **legacy, frozen** |
| lg | 16px | Section padding, default card gaps, horizontal screen padding |
| xl | 20px (legacy) | OTP row / phone-row gaps; **legacy, frozen** |
| 2xl | 24px | Layout gaps — header, card↔form, tab bar |
| 3xl | 32px | Major section breaks, splash main gap |
| 4xl | 40px | Page-level spacing, empty-state padding-y |
| 5xl | 48px | Page-level spacing (splash top) |

Exceptions: **none for Phase 1 beyond the noted legacy 12/20px tokens.** Touch targets: minimum
interactive height is 48px (AppButton base) and 44–56px for OTP input boxes (width 48 / height 56
in `OtpScreen.js`, 44×48 in `BusinessSetupScreen.js`). Back/icon buttons: 38px box (`AuthScreen.js`)
— keep ≥ 38px with adequate hit padding.

## Typography

Declared from the existing `src/theme/typography.js` sizes/weights and the `AppText` variants
(provenance: codebase). The contract binds typography through the **`AppText` variant roles** below
— the executor writes against variants, not raw sizes/weights.

| Role (AppText variant) | Size | Weight | Line Height | Usage in Phase 1 |
|------|------|--------|-------------|------------------|
| title | 28 | bold (700) | 34 | Splash brand, screen titles (AppHeader), Business-setup heading |
| heading | 22 | semibold (600) | 28 | Section headers, empty-state titles, card titles, role-selection labels |
| body | 16 | regular (400) | 24 | Body copy, subtitles, hero copy, form help text |
| label | 14 | medium (500) | 20 | Input labels, button labels, field values, table/row labels |
| caption | 12 | medium (500) | 16 | Helper text, OTP hints, timestamps, badge labels, footer brand text |

**Line-height convention:** body 1.5 (24/16), title 1.21 (34/28), heading 1.27 (28/22). These are
the pre-existing AppText values — do not override.

**Weights used:** 400 (regular), 500 (medium), 600 (semibold), 700 (bold). The 600/700 semibold-bold
pair is the emphasis axis; 400 is body. (Existing system has 4 weights — documented as-is, not
reduced.)

| Border | `border` `#E3E7EE` | Input borders, card hairlines, tab bar top border |

confirmation trigger. No other destructive actions exist in Phase 1.

## Copywriting Contract

Grounded in the exact screens Phase 1 touches. **Primary navigation verb is "Continue"; the phase's
auth CTAs are "Send OTP", "Verify & Continue", and "Complete Signup."** All copy is US-English,
`start case` on buttons, sentence case elsewhere.

| Element | Copy |
|---------|------|
| Welcome CTA | **Continue with Mobile** → opens role-aware login |
| Login CTA (mobile step) | **Send OTP** (idle) / **Sending...** (busy) — disabled until 10-digit mobile entered |
| Login CTA (OTP step) | **Verify & Continue** (idle) / **Verifying...** (busy) — disabled until 6 digits complete |
| Password step CTA (driver/pump/employee) | **Log in** / **Logging in...** |
| Owner login (OTP only) | After Verify & Continue → straight to app (no password step) |
| Resend OTP | **Resend OTP** (enabled) / **Resend code in 0:NN** (countdown, disabled) |
| Change number | **Change number** — returns to mobile entry, clears OTP |
| Business setup CTA | **Complete Signup** (disabled until mobile verified) |
| Business setup mobile verify | **Verify** / **Sending...** then **Verify OTP** / **Verifying...** |
| Verified badge | **Verified** (success tone, check-circle icon) |
| Empty state heading | **Nothing here yet** |
| Empty state body | **No data to show right now. Pull to refresh or try again in a moment.** (+ optional **Create / Retry** action when a CTA applies) |
| Error state (validation) | **[Specific field message]** e.g. "Enter a valid 10-digit mobile number", "OTP must be 6 digits" — shown under field, `danger` tone |
| Error state (network/offline) | **You're offline** / **Can't reach the server right now. Check your connection and try again.** |
| Error state (server) | **Something went wrong on our side. Please try again in a moment.** (+ **Retry** action) |
| Session expired | **Your session has expired.** / **For security, please log in again. Your unsaved work is safe.** |
| Logout confirmation | Trigger: **Log out**. Confirm dialog: **Log out?** / body: **Ending the session also ends it on the server. You'll need to sign in again.** Buttons: **Cancel** / **Log out** (danger). |
| Login error fallback | **Unable to log in. Please try again.** |

**Destructive actions in phase:** exactly **one** — **Log out** (server-side session end, AUTH-05).
Confirmation approach: in-app confirmation dialog (`Alert.alert`) with explicit Cancel / Log out; the
destroy action is the only `danger`-toned interactive element. No other destructive element exists.

## Role & Asset Considerations (Phase 1 additions)

These are gaps this contract adds — they do not exist in the current codebase:

1. **Role: 4 hard-coded roles** from the backend — `owner` (1), `driver` (2), `petrol-pump` (3),
   `employee/admin` (4). Phase 1 introduces **role-aware login**: the mobile/OTP step is shared;
   after the mobile is identified, the credential step branches (owner → OTP only; driver/pump/
   employee → OTP + password). The UI must surface which role is logging in.
   - **New `RoleBadge`** (or `StatusBadge` `role` tones): pill showing the current role on any
     post-login screen touched by Phase 1 (e.g. a session/user header not present today). Label
     mapping: Owner / Driver / Petrol Pump / Employee.
2. **Offline awareness (DATA-02):** an `OfflineBanner` at the top of data surfaces when the network
   is unreachable, using muted `warning`-adjacent tone. Distinct from the full-screen error state.
3. **Session-expiry (AUTH-07):** a non-destructive, dismissible banner/sheet on `authentication`
   (401) re-auth, preserving local state; re-authentication returns the user to where they were.

## UI Considerations

> State coverage per the ui-phase probe taxonomy. Copy for empty/error/offline lives in the
> Copywriting Contract above and is referenced (not restated) here. Loading is a Phase 1 hard
> requirement (DATA-02) — the shared adapter must expose loading consistently.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| loading | login mobile form, OTP form, password form, business-setup submit | ✅ covered | Button label swaps to "Sending... / Verifying... / Logging in..." while `isSubmitting`; AppButton `disabled` + 0.48 opacity; logout confirms server round-trip. |

| error | login / OTP / password / business-setup | ✅ covered | Field-level `danger` message under input; action re-enabled on retry. |
| error | network / server (adapter) | ✅ covered | Full-screen surface copy per Copywriting Contract; **Retry** re-invokes action. |
| partial | business-setup form | ✅ covered | OTP reveal is gated: mobile field editable until verified; "Complete Signup" disabled until `mobileVerified` — matches existing pattern. |
| zero-one-many | role selection (4 roles) | ✅ covered | Role list renders consistently at 1 vs 4 roles; each `RoleBadge` a constant width chip. |
| overflow | offline banner / session-expiry body | 🧪 backstop | Long copy wraps (maxWidth on subtitle pattern); held-out visual check that banner text reflows on narrow screens. |
| long-text | login/OTP error + help copy | ✅ covered | Wrap with `textAlign` center where full-width; `caption`/`label` line-heights per typography table. |
